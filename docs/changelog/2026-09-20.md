# 1. Monkeytype three-line viewport regression

## Problem

The normal Monkeytype typing viewport is intended to remain around three visible lines.

The custom EN-VN learning CSS had changed the wrapper overflow behavior so content below the computed wrapper height could remain visible. With longer custom text this looked like the test suddenly expanded from three lines into the full text and could cause overlapping content.

## Root cause

The core Monkeytype code was still calculating the wrapper height correctly.

The regression came from the custom learning override on:

~~~text
#wordsWrapper.en-vn-learning
~~~

which effectively defeated the clipping behavior.

## Fix

The core height remains authoritative.

The learning wrapper now allows translation content to extend above and slightly beyond the horizontal edges while clipping the typing content at the bottom:

~~~text
overflow: visible
clip-path: inset(-8rem -8rem 0 -8rem)
~~~

The EN-VN line-spacing options were also tuned so held translations have more breathing room:

~~~text
comfortable = 0.52em top/bottom word margin
wide        = 0.70em top/bottom word margin
~~~

The existing pseudo-element held-tooltip approach remains in place because Monkeytype rewrites each word's inner HTML while typing.

# 2. Monkeytype optional Recall Typing mode

A new optional setting was added to the existing Custom Text EN-VN learning controls:

~~~text
recall typing
~~~

Default:

~~~text
disabled
~~~

When enabled:

1. only English words/phrases that match the EN-VN dictionary become recall targets,
2. their English letters are hidden before typing,
3. punctuation and structural characters remain visible,
4. correct/corrected letters reveal progressively as the user types,
5. incorrect target letters remain hidden rather than leaking the answer,
6. the Vietnamese learning cue can appear through the existing tooltip/top display,
7. the top display hides the English source while Recall mode is active,
8. English pronunciation still uses the existing pronunciation settings.

The recall target is prepared during the normal Monkeytype word-render phase instead of being hidden only after the first keystroke. This prevents answer flashing and layout jumps.

Learning information is triggered when the target becomes the active word. The existing first-keystroke trigger remains compatible with normal non-Recall EN-VN learning.

Phrase matching reuses one longest-match implementation:

~~~text
findDictionaryMatch(...)
~~~

so entries such as:

~~~text
dependency injection = tiêm phụ thuộc
~~~

are treated as the longest matching phrase instead of duplicating matching logic in the UI.

The setting is persisted inside:

~~~text
personalEnVnTranslationSettings
~~~

with backward-compatible migration.

# 5. Vocabulary Shooter Target Rush readability

Target Rush was refined for dense boards.

The presentation now follows these rules:

- no rectangular word boxes,
- dormant targets use subdued text,
- spotlight/danger/active states use glow,
- the board uses no more than four rows,
- additional targets expand horizontally into more columns,
- font size adapts to available cell width and phrase length,
- very long/dense phrases can shrink further instead of overlapping adjacent cells.

Current layout rule:

~~~text
rows <= 4
columns = ceil(targetCount / rows)
~~~

The active/danger word still remains visually distinct from dormant words.

# 6. Vocabulary Shooter restart flow

Shooter now uses a deliberate two-step keyboard restart flow.

Default quick-restart key for a new installation:

~~~text
Escape
~~~

Existing saved Tab/Escape preference is preserved during settings migration.

Behavior:

~~~text
quick restart key
→ reset to clean ready state
→ show "Ready when you are"

next normal key
→ 3-second countdown
→ game starts
~~~

The Start / Restart button begins the countdown directly.

Shortcut handling was kept in the UI layer rather than duplicated inside the game engine.

The quick-restart shortcut is ignored while the user is interacting with settings/vocabulary dialogs.

The opposite key remains available as target unlock.

# 9. Portal loading experience

The Portal still follows the performance rule:

~~~text
only the selected game iframe is mounted
~~~

Inactive games are not kept alive in the background.

To avoid a blank/gray-looking wait while a child app boots, the Portal now:

- preconnects to registered game origins,
- displays a small local "Loading game..." overlay,
- fades the iframe in after its load event,
- removes the loader afterward.

This does not pretend that Monkeytype's development bootstrap cost disappears. It replaces the visually empty state while preserving the low-memory single-iframe architecture.

# 10. Full-text reading option analyzed

A future Monkeytype Custom Text setting for reading the full text is feasible without downloading video/audio assets.

Recommended direction:

~~~text
browser/system Web Speech API
SpeechSynthesis
SpeechSynthesisUtterance
~~~

This deliberately reuses the same browser/system speech mechanism already used by the current learning features.

Recommended future controls:

~~~text
Full text reader: enabled/disabled
Language: Auto / English / Vietnamese
Voice: local system voice
Rate: adjustable
Volume: adjustable
Play / Stop
optional Pause / Resume
~~~

For long text, sentence/short-paragraph chunking should be used instead of pushing one very large utterance.

Performance/offline rule:

- prefer local system voices,
- do not fetch generated MP3/audio for every reading,
- do not add a large neural TTS/WebAssembly model to the frontend,
- do not require a cloud TTS service for core use,
- if a local Vietnamese voice is unavailable, report that clearly instead of silently requiring network TTS.

This option is documented as a recommendation only. It was not added to the game in this implementation pass.
