# 1. Monkeytype three-line viewport regression

## Problem

The normal Monkeytype typing viewport is intended to remain around three visible lines.

The custom EN-VN learning CSS had changed the wrapper overflow behavior so content below the computed wrapper height could remain visible. With longer custom text this looked like the test suddenly expanded from three lines into the full text and could cause overlapping content.

## Root cause

The core Monkeytype code was still calculating the wrapper height correctly.

The regression came from the custom learning override on:

~~~text
#wordsWrapper.en-vn-learning
~~~

which effectively defeated the clipping behavior.

## Fix

The core height remains authoritative.

The learning wrapper now allows translation content to extend above and slightly beyond the horizontal edges while clipping the typing content at the bottom:

~~~text
overflow: visible
clip-path: inset(-8rem -8rem 0 -8rem)
~~~

The EN-VN line-spacing options were also tuned so held translations have more breathing room:

~~~text
comfortable = 0.52em top/bottom word margin
wide        = 0.70em top/bottom word margin
~~~

The existing pseudo-element held-tooltip approach remains in place because Monkeytype rewrites each word's inner HTML while typing.

# 2. Monkeytype optional Recall Typing mode

A new optional setting was added to the existing Custom Text EN-VN learning controls:

~~~text
recall typing
~~~

Default:

~~~text
disabled
~~~

When enabled:

1. only English words/phrases that match the EN-VN dictionary become recall targets,
2. their English letters are hidden before typing,
3. punctuation and structural characters remain visible,
4. correct/corrected letters reveal progressively as the user types,
5. incorrect target letters remain hidden rather than leaking the answer,
6. the Vietnamese learning cue can appear through the existing tooltip/top display,
7. the top display hides the English source while Recall mode is active,
8. English pronunciation still uses the existing pronunciation settings.

The recall target is prepared during the normal Monkeytype word-render phase instead of being hidden only after the first keystroke. This prevents answer flashing and layout jumps.

Learning information is triggered when the target becomes the active word. The existing first-keystroke trigger remains compatible with normal non-Recall EN-VN learning.

Phrase matching reuses one longest-match implementation:

~~~text
findDictionaryMatch(...)
~~~

so entries such as:

~~~text
dependency injection = tiêm phụ thuộc
~~~

are treated as the longest matching phrase instead of duplicating matching logic in the UI.

The setting is persisted inside:

~~~text
personalEnVnTranslationSettings
~~~

with backward-compatible migration.

# 10. Monkeytype full-text reader implemented

The previously analyzed full-text reader is now implemented inside the Monkeytype Custom Text settings.

Implementation:

~~~text
browser/system Web Speech API
SpeechSynthesis
SpeechSynthesisUtterance
~~~

No external TTS library, downloaded audio file, video asset, cloud TTS service or in-browser neural speech model was added.

Controls:

~~~text
Full text reader: enabled/disabled
Language: Auto / English / Vietnamese
Voice: local system voices only
Rate: 0.5x → 2.0x
Volume: 0 → 100
Play / Restart
Pause / Resume
Stop
~~~

The reader supports English and Vietnamese.

Auto mode detects Vietnamese-specific marks; otherwise it defaults to English. The user can explicitly choose English or Vietnamese when auto detection is not appropriate.

Voice selection is intentionally restricted to voices where the browser reports:

~~~text
voice.localService === true
~~~

If no matching local English/Vietnamese voice is available, the UI reports that instead of silently falling back to remote/cloud speech.

Long text is split into short sentence/word chunks before speech is queued. Oversized single tokens are also split so one pathological token does not create an excessively large utterance.

Speech coordination rule:

~~~text
full-text reader
and
existing per-word English pronunciation
share the browser SpeechSynthesis queue
~~~

Starting one stops the other first, so audio does not overlap or queue unexpectedly.

Pause/Resume state is normalized after cancellation so a paused reader cannot leave later pronunciation or restart playback stuck in a paused browser speech state.

Reader settings are persisted in:

~~~text
personalEnVnTranslationSettings
~~~

with backward-compatible migration.

Focused tests cover:

- Auto English/Vietnamese selection,
- explicit language override,
- sentence/word chunking,
- oversized-token chunking,
- blank input.

# 13. One-command static Play mode

The user confirmed that Play mode should not perform development/update responsibilities.

New root command:

~~~bash
./play.sh
~~~

The responsibilities are intentionally separated:

~~~text
./dev.sh
→ Git pull
→ submodule synchronization
→ dependency preparation
→ Vite development services

./play.sh
→ no Git pull
→ no submodule update
→ no dependency install
→ static builds only when local source is newer
→ nginx static Play mode
→ open the game library
~~~

## Play startup flow

~~~text
1. stop old typing-game development listeners on 3000/3001/3002/3100
2. inspect static outputs independently for Portal, Shooter, Recall and Monkeytype
3. rebuild only missing/stale apps
4. keep existing current builds untouched
5. switch nginx to the static Play configuration only when needed
6. open https://typing-game.local
~~~

The development-port cleanup gained a `--project-only` mode.

This is important for Play mode:

- project-owned Vite listeners are stopped so they do not waste CPU/RAM,
- unrelated applications using the same development port numbers are not killed,
- unrelated port usage does not block static Play mode because those ports are not required by nginx static serving.

Build freshness is based on local file modification time versus each app's generated `dist/index.html`.

Generated/cached directories such as `node_modules`, `dist`, `.turbo` and coverage output are excluded from freshness scanning.

If a build is stale but pnpm is unavailable, Play mode stops with a clear message rather than trying to install anything.

CI now validates:

~~~text
bash -n play.sh
bash play.sh --help
invalid play.sh arguments are rejected
~~~

No remote update behavior was added to Play mode.

# 14. macOS Bash 3.2 empty-port cleanup fix

A real local `./dev.sh` run failed during the development-port cleanup step with:

~~~text
scripts/cleanup-dev-ports.sh: line 56: targets[0]: unbound variable
ELIFECYCLE Command failed with exit code 1
~~~

Root cause:

- the script uses `set -u`,
- no stale typing-game listener existed,
- therefore the `targets` array was empty,
- macOS ships an older Bash 3.2 whose empty-array expansion behavior with nounset differs from newer Bash versions.

The first guard based on array length was made stricter after review.

Final fix:

~~~text
targets=()
target_count=0

when a project PID is added:
→ append target
→ increment target_count

only expand targets[@] when target_count > 0
~~~

This avoids touching the empty array at all on the Bash 3.2 path.

The same rule is used for normal cleanup and `--project-only` cleanup.

Platform CI now also smoke-tests an empty `--project-only` cleanup call in addition to shell syntax validation.

# 17. Monkeytype Stop on Error policy refinement

A hands-on test clarified that the existing `forgive corrected errors` feature was useful but not identical to the original requirement.

The existing mode is preserved.

It continues to:

~~~text
first blocked error
→ can count

repeated blocked attempts
→ no additional accuracy penalties

correct the blocked input
→ restore/forgive the original blocked accuracy penalty
~~~

A new independent option was added:

~~~text
ignore repeated blocked errors
~~~

Its rule is:

~~~text
first blocked error
→ penalty remains

repeated blocked attempts
→ ignored for accuracy

correct later
→ original first penalty remains
~~~

This directly covers the fast-typing scenario where the typist may enter several more keys before noticing the Stop on Error block.

The two accuracy modes are mutually exclusive in Settings.

A second option was also added:

~~~text
keep first wrong letter
~~~

For `stop on error = letter`:

~~~text
first wrong character
→ remains in the word as the normal red/incorrect character

later typing
→ blocked

Backspace/delete wrong character
→ allowed

correct character
→ continue
~~~

The implementation reuses Monkeytype's existing input/event/delete pipeline rather than creating a second input model.

## Leveling policy

The final ranking policy now combines:

- English frequency,
- CEFR reference where available,
- usefulness for Vietnamese learners,
- spelling difficulty,
- pronunciation difficulty,
- abstractness,
- technical/general balance.

CEFR is a reference rather than a direct level number.

The documented broad plan is A1-heavy levels 001-012, A2-heavy 013-028,
B1-heavy 029-046, B2-heavy 047-065, C1-heavy 066-082,
C2-heavy 083-094, with 095-100 reserved for manually selected
very advanced/abstract/technical/rare-but-useful vocabulary.

candidate source and CEFR-J as a difficulty reference.

~~~

# 25. Full vocabulary build gate

Platform CI remains lightweight for normal commits, but a guarded full-data job is now available.

A commit whose message contains:

~~~text
[vocab-full]
~~~

runs the normal integration job first. Only after that job passes, GitHub Actions:

~~~text
1. checks out the pinned vocabulary source revisions
2. prepares candidates
3. builds the 18,000-entry target with a 15,000-entry hard minimum
4. validates the resulting 100-level library
5. commits shared/vocabulary/levels plus generated index/lookup back to main
~~~

The generated commit uses:

~~~text
[skip ci]
~~~

so the data commit does not recursively start another full build.

This gate exists specifically so the large production library is built from the real pinned
datasets in GitHub's runtime instead of assuming that syntax-valid pipeline code will also
produce enough trusted entries.

## Karaoke Typing

Added a fourth independent typing game:

~~~text
sinhvienaiti/karaoke-typing
~~~

The new child repository was implemented as a clean TypeScript/Vite app with:

- YouTube URL/video-ID playback,
- local audio/video playback without uploading media,
- standard and enhanced LRC parsing,
- synchronized karaoke lyric highlighting,
- Normal, Easy, Blind and Blank modes,
- score, combo, accuracy, completed/skipped line tracking,
- lyric offset and playback-rate controls,
- result/restart flow,
- unit tests and child CI.

The first child CI run exposed an invalid test assumption: the test string `not-a-video` is exactly 11 characters and syntactically matches a YouTube video ID. The test was corrected to use a truly invalid-length value.

Before final integration, Easy mode was also stabilized so an expired unfinished line is paused once instead of repeatedly seeking every animation frame. Lyric DOM rendering was cached by line/typed/sung state to avoid rebuilding character spans when nothing visible changed. LRC offset handling was made independent of where the offset metadata appears.

Platform integration added:

~~~text
games/karaoke-typing
https://typing-game.local/karaoke-typing
https://karaoke.typing-game.local
port 3003
~~~

The platform registry, dev/build/bootstrap/play scripts, nginx dev/play configurations, local certificate host list and documentation were extended. Existing game source repositories were not modified.

Because the new child repository is currently private, parent CI does not attempt to clone it with the parent repository token. Child build/test validation remains in `sinhvienaiti/karaoke-typing`; parent CI verifies the gitlink and continues testing its existing public integration targets.

A review also found that the old unconditional submodule initialization would make focused commands such as `./dev.sh monkeytype` require access to the new private Karaoke repository. Bootstrap was changed so focused targets initialize only their own game submodule; `all` still initializes the complete platform.

The YouTube API loader was also hardened so a failed script load clears its cached promise and can be retried without reloading the page.


A second gameplay review found that manual Pause still allowed typing and scoring while media time was frozen. Input and Tab-skip are now blocked during a normal manual pause, while Easy-mode recovery pause intentionally remains typeable. A regression test covers this pause-input policy.
