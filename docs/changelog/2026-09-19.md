# 35. Vocabulary Shooter multi-mode expansion requested

After the first integrated version was stable, the user defined the next major Shooter direction.

This is a design/planning update; the new modes are not yet implemented in this changelog entry.

## Confirmed requirements

Vocabulary Shooter should no longer be a single-mode lives game.

The current mode becomes Classic Survival.

Three additional modes were requested.

### Bounce / Relax

- words remain alive on screen,
- each word moves continuously with a velocity vector,
- it reflects from the game-frame walls like a billiard object,
- it must not randomly steer itself while travelling,
- the user configures the maximum number of simultaneous words,
- exceeding that count loses the run,
- correctly typed words are removed with the normal pronunciation/VN/IPA success flow.

### Time Attack

- user configures a fixed duration,
- example requirement: 100 seconds,
- the game runs until the timer expires,
- correct and missed words are counted,
- results report the player's work during that time window.

### Target Rush

- user configures a pool size such as 70 words,
- the pool is randomized,
- one word is spotlighted,
- target switching happens on a fixed schedule even if the previous word is not finished,
- example timing: 3 seconds spotlight,
- if unfinished at 3s, the old word begins diving toward the player for another 2 seconds,
- the next target lights immediately when the old word begins its dive,
- therefore the old word has 5 seconds total from activation to impact,
- the old word remains typable during the 2-second dive,
- if it reaches the player, the word impacts/explodes and the run is lost.

## Keyboard control

The user specifically asked for Monkeytype-like quick restart.

Required setting:

~~~text
Tab or Escape
~~~

Recommended conflict handling:

~~~text
restart Tab
→ unlock uses Escape

restart Escape
→ unlock uses Tab
~~~

## Audio and visual direction

The user wants the game to feel significantly richer.

Requested direction:

- background music,
- danger/alarm music when close to losing,
- smooth attractive success effects,
- a bubble/water-pop style successful-hit effect inspired by the reference video,
- more varied and motivating feedback.

The user explicitly rejected an approach where attractive ideas are added without regard to machine load.

The rule is:

~~~text
visual quality and performance must improve together
~~~

## Research/design conclusions

The solution was informed by patterns from established typing games:

- typing-shooter target lock and escalating pressure,
- timed challenge structures,
- accuracy/speed/result feedback,
- danger-state visual signaling,
- adaptive pacing as an optional future enhancement.

The project should use these as design lessons, not clone another game.

## Architecture recommendation

Before adding all modes to the existing large Game.ts, use a small mode-controller split:

~~~text
src/game/
├── Game.ts
├── mode-types.ts
└── modes/
    ├── ClassicMode.ts
    ├── BounceMode.ts
    ├── TimeAttackMode.ts
    └── TargetRushMode.ts
~~~

Shared audio/effect managers are recommended.

This is intended to prevent mode-specific conditions from making Game.ts unmaintainable without creating a large framework.

# 36. Target Rush top Learning Panel clarified

The user added an important Target Rush-specific learning requirement.

This changes the earlier assumption that every Shooter mode reveals learning information only after successful completion.

## Confirmed Target Rush exception

When a word becomes the current spotlight target:

~~~text
spotlight activates
→ show Vietnamese meaning in a dedicated top panel
→ show IPA directly below
→ pronounce the English word immediately
~~~

The panel must be large, clear and visually polished.

It must occupy reserved space above the game/target field.

It must **not** attach the Vietnamese/IPA to the yellow/glowing target itself and must not copy Monkeytype's held-tooltip behavior.

## Panel ownership

The top panel always represents the newest spotlight target.

Example:

~~~text
Target A spotlight
→ panel shows A VN + IPA
→ pronounce A

3s later Target A is unfinished
→ A begins danger dive
→ Target B becomes spotlight immediately
→ panel switches to B VN + IPA
→ cancel old speech and pronounce B
~~~

Target A may still be typed during its dive, but completing A must not cause the panel to jump backward from B to A.

## Success behavior

Because Target Rush provides the pronunciation at spotlight activation, a normal/late successful clear should focus on:

~~~text
shot
explosion
bubble/water effect
score/streak/late-save feedback
~~~

and should not replay the full pronunciation by default.

## Other modes remain unchanged

Classic Survival, Bounce / Relax and Time Attack retain the original rule:

~~~text
before full correct English
→ no VN
→ no IPA
→ no pronunciation

after full correct English
→ VN + IPA + pronunciation
~~~

The detailed design document and project context were updated to make this mode-specific distinction explicit.

# 37. Shooter multi-mode implementation completed

The previously documented Shooter multi-mode design was implemented in the child repository.

Implemented modes:

~~~text
Classic Survival
Bounce / Relax
Time Attack
Target Rush
~~~

## Classic Survival

The original falling-word/lives gameplay is now an explicit mode.

It keeps gradually rising pressure through target count, spawn interval and speed.

## Bounce / Relax

Words move with fixed velocity vectors.

Wall collisions reflect the appropriate velocity component:

~~~text
left/right wall
→ vx changes sign

top/bottom wall
→ vy changes sign

corner
→ both can change sign
~~~

Words do not randomly steer while travelling.

The run fails only after the configured active-word capacity is exceeded.

Full word-to-word physical collision was intentionally not added because it was not required and would add unnecessary O(n²)-style complexity/jitter.

## Time Attack

A fixed-duration mode was added.

Default design supports the user's 100-second case.

Missed falling words increment misses and are removed instead of ending the run.

The configured timer is the end condition.

The final seconds provide countdown/danger feedback.

## Target Rush

A configured target pool is shuffled.

If the vocabulary is smaller than the requested target count, shuffled cycles can refill the requested pool size.

One spotlight target is active on a fixed cadence.

Example:

~~~text
3s spotlight
+
2s danger dive
~~~

At the spotlight deadline, an unfinished old target begins its dive and the next target activates immediately.

The old danger target remains typable.

A late save receives stronger feedback.

Impact with the player ends the run.

## Target Rush Learning Panel

A fixed panel above the target field now shows:

~~~text
Vietnamese meaning
IPA
~~~

when the spotlight changes.

English pronunciation plays immediately at spotlight activation.

Older danger targets do not take over the panel.

The highlighted board target stays English-only.

## Keyboard-first restart

Quick restart setting:

~~~text
Tab
or
Escape
~~~

The other key becomes target unlock.

The shortcut does not hijack normal input/settings dialog controls.

The results screen can also be replayed through the configured keyboard restart.

## Results

A shared results dialog reports common metrics such as:

~~~text
score
correct words
missed words
wrong keys
accuracy
WPM
characters
max streak
elapsed time
average word time
~~~

and mode-specific information such as Bounce maximum active words and Target Rush late saves.

# 39. Monkeytype corrected-error accuracy option

A new optional Monkeytype setting was implemented after the Shooter review.

Setting:

~~~text
forgive corrected errors
~~~

Internal key:

~~~text
forgiveCorrectedErrors
~~~

Default:

~~~text
off
~~~

It is effective only with Stop on Error.

## Why it was added

The user uses Stop on Error to force correction before moving forward.

The old behavior could keep reducing accuracy when the user was already blocked on the same error/word and continued typing.

The user wanted two changes:

1. do not repeatedly penalize accuracy while still blocked by the same unresolved mistake,
2. if the mistake is actually corrected, restore the accuracy penalty.

## Letter mode

Repeated wrong attempts at the same blocked character only have one countable accuracy error.

When the correct character is typed, that blocked error becomes forgiven.

## Word mode

Only the first error in the currently incorrect/blocked word needs to affect accuracy.

Further wrong keystrokes in the same blocked word are marked as ignored for accuracy.

When the word becomes correct again, previous countable errors for that blocked word are forgiven.

Deletion/backspace correction is also handled when deleting leaves the current word exactly equal to its target text.

## Event/stat design

The underlying input event remains in the event log but can be marked:

~~~text
accuracyIgnored: true
~~~

This keeps the event history truthful while allowing the accuracy metric to reflect successful correction.

The live cache is adjusted incrementally; it does not rescan the full test log every time a mistake is corrected.

Final accuracy and error-history calculations ignore forgiven events.

## Tests

Targeted tests were added for:

- repeated blocked letter attempts,
- letter correction restoring 100% live/final accuracy,
- option-off compatibility,
- word-level repeated errors,
- word correction restoring accuracy,
- direct accuracy stats with ignored events.

# 42. Recall Typing separated into a new game

The hidden-word spelling idea was reconsidered before implementation.

Instead of adding it as another Monkeytype mode/setting, it is now planned as a separate game.

## Why

The behavior is meaningfully different from Monkeytype's normal typing flow:

~~~text
Monkeytype
→ visible target text
→ speed/accuracy typing

Recall Typing
→ hidden English spelling
→ recall from pronunciation/meaning
→ correct letters reveal progressively
~~~

Keeping it separate improves:

- discoverability in the Game Library,
- simpler per-game settings,
- clearer learning purpose,
- maintainability,
- lower risk of breaking/upstream-diverging Monkeytype,
- consistency with the one-game-one-repository architecture.

## Planned structure

~~~text
new repo:
sinhvienaiti/recall-typing

parent submodule:
games/recall-typing

public route:
/recall-typing

internal origin:
recall.typing-game.local
~~~

## Monkeytype scope

Monkeytype keeps:

- normal typing,
- custom EN-VN translation learning,
- pronunciation,
- corrected-error accuracy forgiveness.

The hidden recall/spelling mechanic will not be added to Monkeytype itself.

## Recall Typing core

~~~text
English target hidden
→ correct characters reveal one by one
→ wrong characters reveal nothing
→ VN/IPA/pronunciation can act as hints
→ phrase spacing/punctuation remains readable
→ complete target produces success feedback
~~~

This is now documented as a separate game design.
