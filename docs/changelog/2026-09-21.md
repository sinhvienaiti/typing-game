## Rapid pronunciation queue fix

### Request

When Vocabulary Shooter received two correct words very quickly, the second word could fail to be pronounced while the first pronunciation was still playing. The same speech pattern was reviewed across the other games.

### Root cause

Vocabulary Shooter and Recall Typing both called:

~~~text
speechSynthesis.cancel()
speechSynthesis.speak(...)
~~~

for every new word.

The EN-VN pronunciation path in Monkeytype also cancelled the shared browser speech queue before every per-word pronunciation through `stopTextReader()`.

On rapid consecutive words this cancel-and-immediate-speak pattern can discard or swallow the later utterance instead of reliably playing every word.

### Fix

Per-word pronunciation no longer cancels the active utterance.

New words are submitted to the browser speech queue and are spoken in order:

~~~text
word 1 -> speaking
word 2 -> queued
word 3 -> queued
~~~

Explicit lifecycle stops still cancel pending speech when appropriate:

~~~text
restart
run finish
game destroy
tab/background stop path
explicit speech stop
~~~

This avoids stale speech leaking into a new session while preserving every pronunciation during normal fast gameplay.

## Immediate Shooter translation reveal

Vocabulary Shooter previously displayed Vietnamese + IPA only when the projectile reached the completed target and exploded. Because projectiles start near the player at the bottom of the board, targets near the top could delay the translation by roughly a second or more even though the word had already been typed correctly.

The learning feedback is now decoupled from projectile travel:

~~~text
last correct character
-> word completes
-> VI + IPA reveal starts immediately
-> pronunciation starts
-> projectile keeps flying independently
-> explosion still happens when the projectile reaches the target
~~~

The reveal is positioned slightly below the completed English target and clamped away from the bottom edge so it does not overlap the still-visible pending target while the projectile is travelling.

The existing Reveal duration setting is unchanged. Only the start time moved from projectile impact to word completion.

Projectile feedback was also accelerated so the visual hit does not feel delayed behind the instant learning feedback. Instead of a fixed 1050 px/s speed, each shot now uses a minimum speed of 1800 px/s and scales with distance so travel time is capped at about 0.22 seconds.

## Shared background music across games

Added one parent-owned background music player to the `typing-game` Portal.

The player is persistent: navigating between Home, Monkeytype, Vocabulary Shooter and Recall Typing replaces only the route content/iframe. The Portal shell and music player stay alive, so the current track does not restart when changing games.

Supported sources:

~~~text
Local audio
YouTube URL / video ID
~~~

Local music lives outside Git:

~~~text
shared/music/
~~~

`pnpm music:index` scans browser-supported audio files and writes ignored `shared/music/index.local.json`. `./dev.sh` and `./play.sh` refresh this index automatically. The tracked `shared/music/index.json` remains an empty fallback library.

YouTube tracks are added from the Music menu and persisted in Portal `localStorage`. Only the video ID/title are stored; media is streamed with the YouTube IFrame Player API.

Playback controls/settings:

~~~text
Off / track selection
Play / Pause
Next
Music volume
Auto next
Repeat one
Lower music during pronunciation
Pronunciation music level
~~~

`Auto next` is the default and wraps to the first track after the final Local/YouTube item. `Repeat one` replays the current track.

Pronunciation audio focus:

~~~text
game pronunciation queued/starts
-> child posts speech focus to Portal
-> shared music ducks quickly
-> pronunciation stays clear
-> speech ends
-> music restores smoothly
~~~

Defaults:

~~~text
music volume = 32%
pronunciation ducking = enabled
ducked level = 18% of configured music volume
duck attack ~= 55ms
duck release delay ~= 160ms
volume restore ~= 220ms
~~~

Shooter, Recall and Monkeytype EN-VN send speech-focus signals. Monkeytype Text Reader also participates, including pause/resume state.

Karaoke Typing has full audio priority. Shared music pauses when entering Karaoke and resumes after leaving if it was active beforehand.

Vocabulary Shooter procedural BGM remains only as a fallback. When shared music owns background audio, Shooter procedural BGM is muted while SFX and pronunciation remain available.

## Fix full-height game iframe regression

After the Portal was refactored to keep the shared Music player persistent, all child games could render inside an iframe that collapsed to the browser default iframe height (about 150px). The remaining page area showed only the parent Portal background.

Root cause:

~~~text
.portal-shell
  -> .route-host
      -> .game-stage
          -> iframe height: 100%
~~~

The new `.route-host` wrapper did not provide a definite height contract to the nested `.game-stage` / iframe. The percentage iframe height therefore could not reliably resolve and browsers fell back to the default iframe height.

Fix:

~~~text
.route-host
-> height: 100%

.game-stage
-> width: 100%
-> height: 100%
-> overflow: hidden

.game-frame
-> position: absolute
-> inset: 0
-> width: 100%
-> height: 100%
~~~

The Home route also explicitly fills the route area while keeping its own scrolling.

This is a parent-only layout fix. No child game source was changed.

A CI regression guard was added at `scripts/validate-portal-layout.mjs` so the required full-height layout contract cannot be removed silently in a future Portal refactor.
