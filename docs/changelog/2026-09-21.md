# 2026-09-21

## Rapid pronunciation queue fix

### Request

When Vocabulary Shooter received two correct words very quickly, the second word could fail to be pronounced while the first pronunciation was still playing. The same speech pattern was reviewed across the other games.

### Root cause

Vocabulary Shooter and Recall Typing both called:

~~~text
speechSynthesis.cancel()
speechSynthesis.speak(...)
~~~

for every new word.

The EN-VN pronunciation path in Monkeytype also cancelled the shared browser speech queue before every per-word pronunciation through `stopTextReader()`.

On rapid consecutive words this cancel-and-immediate-speak pattern can discard or swallow the later utterance instead of reliably playing every word.

### Fix

Per-word pronunciation no longer cancels the active utterance.

New words are submitted to the browser speech queue and are spoken in order:

~~~text
word 1 -> speaking
word 2 -> queued
word 3 -> queued
~~~

Explicit lifecycle stops still cancel pending speech when appropriate:

~~~text
restart
run finish
game destroy
tab/background stop path
explicit speech stop
~~~

This avoids stale speech leaking into a new session while preserving every pronunciation during normal fast gameplay.

## Vocabulary level apply feedback

Vocabulary Shooter's Class vocabulary flow was clarified:

- Class and Custom are now selection tabs only; switching tabs does not silently apply a source.
- `Use level` is the explicit Class apply action.
- While a level is loading, the button changes to `Applying…` and is disabled.
- On success, the Vocabulary dialog closes, the game is reset to ready with the selected vocabulary, and a temporary status notice shows the applied level and word count.
- On failure, the dialog remains open and the existing error alert is shown.
- Saving Custom vocabulary now gives the same temporary success notice.
- The Class level select now reuses Shooter's existing dark form-control styling while keeping the native browser select appearance and accessibility behavior.
